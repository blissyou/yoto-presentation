Yocto Linux란?

Yocto Project는 임베디드 장치에 맞는 Linux 시스템을 직접 만드는 빌드 프레임워크입니다.

핵심 설명Ubuntu처럼 완성된 배포판을 설치하는 것이 아니라, 제품에 필요한 Linux 이미지를 조립합니다.
목표: 보드에 맞는 최소 Linux 이미지 만들기
Why Yocto제품용 Linux

Yocto를 사용하는 이유

작게 만들기필요한 패키지만 넣어 이미지 크기를 줄입니다.
재현 가능같은 설정으로 같은 결과물을 다시 빌드할 수 있습니다.
제품 최적화보드, 드라이버, 서비스, 앱을 제품 기준으로 구성합니다.
예: GUI 없는 센서 장치 → 네트워크, 드라이버, 데이터 수집 앱만 포함
CompareDistro vs Yocto

일반 Linux 배포판과 Yocto의 차이

일반 배포판
  • 이미 만들어진 OS를 설치
  • 범용 패키지가 많음
  • 빠른 개발과 테스트에 유리
Yocto
  • OS 이미지를 직접 빌드
  • 필요한 구성만 선택
  • 양산 제품과 장기 유지보수에 유리

요약하면, 배포판은 사용 중심이고 Yocto는 제작 중심입니다.

Layer 구조 예시

핵심 설명Layer는 아래 기반 위에 필요한 설정을 겹겹이 쌓는 구조입니다. 제품 변경사항을 원본과 분리해 관리합니다.
meta-product제품 앱, systemd 서비스, 이미지 구성
▲
meta-application사용자 프로그램, 설정 파일, 패키지 추가
▲
meta-bsp / meta-boardBootloader, Kernel config, Device Tree, 드라이버
▲
Kernel / Poky / OE-CoreLinux Kernel, 기본 빌드 시스템, 공통 Recipe

Tip: Kernel과 보드 의존 설정은 보통 BSP Layer에서 다루고, 제품 기능은 상위 Layer에서 분리합니다.

임베디드 리눅스에서 Yocto가 중요한 이유

하드웨어 맞춤CPU, 보드, 부트로더, 커널 설정을 제품에 맞춥니다.
보안 관리불필요한 패키지를 줄이고 취약점 대응 범위를 관리합니다.
장기 유지동일한 빌드 기준으로 버전과 변경 이력을 추적합니다.
제품 관점: "개발 PC에서 된다"보다 "양산 장비에서 반복 가능하다"가 중요

실제 프로젝트에서 자주 만나는 문제

패키지 추가IMAGE_INSTALL에 필요한 패키지를 넣습니다.
파일 복사Recipe의 do_install에서 대상 경로로 설치합니다.
서비스 등록systemd service 파일을 포함하고 enable 처리합니다.
드라이버 포함커널 설정, 모듈, device tree를 함께 확인합니다.
빌드 실패log.do_compile, log.do_install을 먼저 확인합니다.
버전 충돌Layer 우선순위와 Recipe append 파일을 점검합니다.

간단한 예시 코드

아래 Recipe는 로컬 파일을 이미지 안의 /usr/bin으로 복사합니다.

SUMMARY = "Install simple script" LICENSE = "MIT" SRC_URI = "file://hello.sh" do_install() { install -d ${D}${bindir} install -m 0755 ${WORKDIR}/hello.sh ${D}${bindir}/hello } FILES:${PN} += "${bindir}/hello"
이미지에 추가: IMAGE_INSTALL:append = " hello-script"
